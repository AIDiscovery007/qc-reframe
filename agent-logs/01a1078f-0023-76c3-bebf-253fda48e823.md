### 建议实施设计

1. 将 projectId 定义为稳定身份，既有 ID 原样保留；图片 SHA256 仅负责资源校验/去重。导入查重独立于当前参考图，重复收集原图不得覆盖已经调整的项目输入，也不得因编辑后的图片与另一项目相同而切换归属。
2. 保留新建/收集入口，新增按明确 projectId 更新当前输入的接口。旋转和角色互换走更新接口；项目内“替换参考图”也应遵循原位编辑语义，显式“新建项目”才走创建。当前引用、当前模式主体编排与任务指令一起保存，持久成功后更新界面；用输入 revision 防并发覆盖，旧回包不得影响已切换的项目。
3. 项目当前参考图供后续新作业，当前模式主体/指令按模式隔离保存；历史任务/生图各自引用不可变快照，后台在途任务继续使用提交时输入。更新参考后，受影响路径的新作业须重新逆向，旧版本仍可显式查看与复用其原始输入，不能把旧 Prompt 默认为新图的结果。打开项目默认恢复最新工作输入，查看历史不回写当前输入。
4. /jobs 以显式项目归属及有效输入版本校验创建快照；移除“项目 ID 必须等于图片哈希”的耦合但保留 images.read 的资源校验。启动迁移优先尊重已存在的合法 projectId，只对缺失归属的旧记录按旧规则补齐；历史任务恢复不覆盖项目最新输入。
5. 互换尽量只交换资产引用（超过主体限制时才需压缩生成新资产）；旋转保留新图，旧图无任何当前/历史引用时回收。有历史引用则保留必要原图，不能原地覆盖共享文件。新增当前主体字段同步纳入回收与删除扫描。
6. 本轮不自动合并截图中的现存项目；旧数据没有可靠编辑血缘。后续可对用户明确指定的两个项目做有备份、可核验的定向归并，保留任务与生成记录，避免按视觉相似度批量合并。
