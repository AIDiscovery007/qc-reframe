# QC-Reframe v0.8.0 · 插件内升级，开发版与发行版分开运行

2026-11-27。

[← 更新日志](https://github.com/AIDiscovery007/qc-reframe/blob/v0.8.0/browser-extension/docs/releases/README.md) · [安装与升级](https://github.com/AIDiscovery007/qc-reframe/blob/v0.8.0/browser-extension/docs/INSTALL_WITH_CODEX.md) · [首页 / Home](https://github.com/AIDiscovery007/qc-reframe/blob/v0.8.0/README.zh-CN.md) · [GitHub Release](https://github.com/AIDiscovery007/qc-reframe/releases/tag/v0.8.0)

**In English:** from this version, a one-command install upgrades itself from the extension: **Settings** (设置中心) → **Local connection** (本机连接) → **Upgrade** (升级到). The upgrade checks a signed release, keeps your projects and settings, puts the old version back if the new one cannot start, then reloads the extension. To get v0.8.0 from v0.7.0, run the install command once more. Developers can now run a separate dev build and service from a source checkout next to the release.

## 在插件里升级

- 有新的正式版本时，侧栏连接状态旁显示「新版本」。打开「设置中心 › 本机连接」，可以看到当前版本、最新版本和「查看更新说明」，点「升级到 X」并确认即可。
- 升级时，本机服务停止一到两分钟。完成后服务自动重新启动，扩展重新加载并回到「本机连接」。项目、图片、配对与设置都保留；未保存的编辑会丢失，已打开的网页需刷新后才能继续选图。
- 新版本替换后无法初始化或启动时，安装器把旧文件移回并重新启动旧服务，界面显示失败阶段和「已恢复」的版本。下载、校验或停止阶段失败时什么都不改动，可以稍后重试。详细输出在 `.local/logs/upgrade.log`。
- 逆向、生图、排队批次、模型验证或 Agent CLI 操作进行中时，不能开始升级。升级进行中，服务拒绝新的任务。
- 只有一键安装的运行包、在 macOS 或 Linux、由 `npm start` 或启动器托管的服务可以插件内升级。源码仓库显示最新版本，并提示用 git 更新；终端前台运行的服务会提示先停止再 `npm start`。
- 另一个浏览器里的扩展仍是旧版本时（例如 Chrome 已升级，Codex 内置浏览器还没有），侧栏显示「需重新加载」，点进去重新加载扩展即可。

## 检查更新与隐私

- 打开工作台时，服务每天最多向 GitHub 读取一次最新正式版本；「本机连接」里可以关闭「每天自动检查更新」，也可以手动「检查更新」。
- 检查只请求 GitHub 的固定地址，不发送项目、图片、配对或任何用户数据；GitHub 能看到的是你的 IP 和 `QC-Reframe/版本号` 形式的 User-Agent。更新说明只给链接，不在扩展里渲染 Release 正文。
- 检查失败时显示「无法检查更新」，其他功能不受影响。

## 签名的 Release

- Release 工作流用 Ed25519 私钥签名 `SHA256SUMS`，附上 `SHA256SUMS.sig`。安装器内置对应公钥，插件内升级必须验证签名；终端一键安装遇到有签名的 Release 也会验证。
- 签名私钥只保存在仓库的 Actions secret 里；工作流在单独的步骤中签名，构建和依赖安装拿不到它。

## 一键安装的改进

- 升级前先把旧文件移到 `.qc-reframe-previous/`，新版本初始化和启动都成功后才删除；失败时自动移回并重新启动旧服务。手动重新运行安装命令时同样适用。
- 安装器把每次升级的结果写入 `.local/runtime/upgrade-result.json`，界面据此说明成功、已恢复或失败的阶段。
- 替换中途，浏览器启动器不会唤醒半替换的服务；重新运行安装命令即可完成。
- 修复 macOS 自带的 bash 在 UTF-8（如中文）终端里把路径后的全角标点当作变量名、安装末尾报 `unbound variable` 的问题。v0.7.0 出现这条报错时，安装和服务启动其实已经完成，只是没有打印最后的加载说明。

## 开发版与发行版分开运行（源码仓库）

同一台电脑可以同时用一键安装的发行版，并在源码仓库开发：

| | 发行版 | 开发版 |
| --- | --- | --- |
| 扩展 | `npm run build` → `.output/chrome-mv3`，QC-Reframe | `npm run dev` / `npm run dev:build` → `.output/chrome-mv3-dev`，QC-Reframe Dev |
| 端口 | 43187 | 43197 |
| 服务命令 | `npm run setup / start / stop / status` | `npm run dev:setup / dev:start / dev:stop / dev:status` |
| 数据 | 安装目录的 `.local/` | 源码仓库的 `.local/` |

- 两个扩展的 ID 不同，各自只连接自己的服务；开发版扩展 ID 为 `eefikhmhfflkjpefegnffhhmikfphldf`。macOS 上 `dev:setup` 另注册 `com.qc.reframe.dev` 启动器，不改动发行版的注册。
- 同一数据目录同时只允许一个服务。源码仓库里已经运行 `npm start` 时，`dev:start` 会拒绝并提示先 `npm stop`。
- 一键安装目录里没有开发版构建，`dev:*` 命令会明确拒绝。
- 两个扩展加载在同一个 Chrome 用户里时，网页图片上会出现两个 R 按钮。不调试时可以在扩展页关闭开发版，或把它加载到另一个 Chrome 用户。

## 升级方式与数据

**从 v0.7.0 一键安装升级：** v0.7.0 还没有插件内升级入口，请等任务结束后再运行一次安装命令，然后在扩展管理页点 QC-Reframe 的重新加载按钮，并刷新已打开的网页。之后的版本都可以在插件里升级。

**源码安装：** 保存编辑并等任务结束，更新完整仓库到 `v0.8.0`，运行 `npm run setup`、`npm start`，再重新加载扩展、刷新工作台和网页。

本版不新增扩展权限，无需数据迁移。项目、提示词、图片、生图渠道与服务配置保存在 `.local/`，全部保留。不修改 Codex 或 Pi 的全局配置。

## 验证与已知限制

- 发布前在本机运行完整回归；发布标签的完整回归在 Release 工作流中重新运行，通过后才发布。附件大小与校验值以 Release 页面及 `SHA256SUMS` 为准。
- 安装器的升级、签名校验、下载或校验失败不改动文件、初始化和启动失败回滚、中断后重跑，由自动测试用本机假 Release 在临时目录覆盖。升级卡片的各种状态由合成预览场景覆盖；扩展重新加载与重新打开设置由后台单元测试覆盖。
- 真实的插件内升级要等下一个正式版本发布后才能端到端验证：本版是第一个带升级入口的版本。Chrome 与 Codex 内置浏览器里 `chrome.runtime.reload()` 的实际表现尚未实机验证。
- 插件内升级不支持 Windows。本版未执行真实账户的逆向或生图请求。
