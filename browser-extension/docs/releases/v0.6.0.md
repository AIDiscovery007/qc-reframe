## macOS Codex：打开时按需启动

- 在安装目录执行一次 `npm run launcher:install -- codex`，注册本机启动器。之后打开工作台、轻量面板或主动连接时，若本机服务不可达，后台请求启动本安装的 bridge，再沿用原有 HTTP 自动连接。撤销用 `npm run launcher:uninstall -- codex`，说明见[安装指引](https://github.com/AIDiscovery007/qc-reframe/blob/v0.6.0/browser-extension/docs/INSTALL_WITH_CODEX.md#macos-codex打开时按需启动)。
- 并发打开共用一次启动；既有服务、令牌和数据保留。后台提醒不唤起服务，网络写入失败不重放。启动器不安装、登录或调用 CLI/模型，也不配置开机自启。
- 其他浏览器与平台继续使用 `npm start`。

## 网页面板按需加载

网页上的 Reframe 面板改为用户打开时才由后台注入当前标签页顶层页面；普通网页只加载选图浮层，不再预载完整面板。新增的 `scripting` 权限仅用于这次注入。

## 本机服务与扩展的架构地基

为后续接入更多本机 Agent 及 CLI 客户端，本版重构了内部结构，现有五条创作路径的行为保持不变：

- 本机服务按服务、项目、任务三组路由拆分；请求体与图片解码、批次调度各自独立。逆向 Agent 统一经注册表的适配器运行，Codex 与 Pi 是其中两个适配器，任务按提交时快照解析所用 Agent。
- 无 Origin 的本机客户端可凭本机私有令牌访问同一接口，为未来 CLI 使用方式预留入口；本版尚未提供 CLI 客户端。
- 扩展界面只保留组合与布局，服务健康、生图设置、项目输入与可见性、逆向提交、工作台交接和提示词导出等规则移入独立模块并直接测试。删除未使用的表单、演示页与导出模拟代码。

## 升级方式与数据

1. 保存编辑，等待任务完成或主动取消，再在原 `browser-extension` 目录执行 `npm stop`；前台服务从原终端停止。
2. 保留本地改动与整个 `.local/` 数据目录，更新完整仓库到 `v0.6.0`，在 `browser-extension` 执行 `npm run setup`、`npm start`，核对 `npm run status` 为 `0.6.0`、`ready: true`。Chrome ZIP 仅含浏览器端，不能替代本机服务与技能。
3. 重新加载原扩展，按浏览器提示确认新增的 `nativeMessaging` 与 `scripting` 权限，再刷新工作台和已打开网页；已打开网页在刷新前仍运行旧脚本。ZIP 解压到原加载目录，不删除原扩展、不清空浏览器数据。
4. macOS Codex 用户如需按需启动，执行 `npm run launcher:install -- codex`，再重新加载扩展一次。

无需数据迁移。已有项目、提示词、图片、配置与连接凭据保留；在途与历史任务按原快照解释，缺少 Agent 字段的旧记录仍视为 Codex。不修改 Codex/Pi 全局默认模型。
