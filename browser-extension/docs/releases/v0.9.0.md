# QC-Reframe v0.9.0 · 检查更新与提醒、原图编辑、认得出的角色写出名字

2026-11-28。

[← 更新日志](https://github.com/AIDiscovery007/qc-reframe/blob/v0.9.0/browser-extension/docs/releases/README.md) · [安装与升级](https://github.com/AIDiscovery007/qc-reframe/blob/v0.9.0/browser-extension/docs/INSTALL_WITH_CODEX.md) · [首页 / Home](https://github.com/AIDiscovery007/qc-reframe/blob/v0.9.0/README.zh-CN.md) · [GitHub Release](https://github.com/AIDiscovery007/qc-reframe/releases/tag/v0.9.0)

**In English:** **Settings** can now check for updates on demand and show what the new release changes. After a stable release, the extension icon shows **NEW** and one notification offers to upgrade or skip that version. Full recreate (完整复刻) adds **source-image edit** (原图编辑). The reverse lists editable elements such as face, pose, background and text. You fill in the changes, and the original image is edited while everything else stays the same. Recreate prompts now open with a standard technique term and state framing, placement and orientation precisely, so slight turns no longer come out frontal. Recognizable characters, landmarks and products are named, e.g. Hinata Hyuga (Naruto), and their original traits are kept brief. To upgrade from v0.8.x, open **Settings** (设置中心) → **Local connection** (本机连接) → **Check for updates** (检查更新).

## 设置中心可检查更新，新版本发布后提醒升级或跳过

- 「设置中心 › 本机连接」的「检查更新」按钮与版本信息在同一行。
- 有新的正式版本时，卡片显示当前与最新版本、更新要点、「升级到 X」「查看更新说明」和「跳过此版本」。更新要点取自版本说明的标题，最多 6 条。
- 发布新的正式版本后，不打开插件也会收到提醒：
  - 扩展图标显示 `NEW`；有未查看的任务结果时，仍先显示结果数量。
  - 每个版本只弹一次系统通知，可选「查看并升级」或「跳过此版本」。
- 跳过只停止该版本的提醒，设置页仍可随时升级到它；出现更新的版本时重新提醒。跳过记录保存在服务配置中，重启服务后仍有效。
- 提醒靠本机检查：
  - 扩展每 30 分钟询问一次本机服务。
  - 服务每小时最多向 GitHub 读取一次最新正式版本信息，不发送项目、图片或配对信息。
  - 发版后约一到一个半小时内提醒。
  - 本机服务未运行时不检查，也不唤醒服务。
  - 可在同一卡片关闭「自动检查并提醒新版本」。
- 只有正式 Release 会提醒，预发布与草稿不会。Chrome 与 Codex 内置浏览器各有一个扩展，各提醒一次。
- GitHub 限制访问频率时，提示访问受限及大约几分钟后可重试，不再显示为网络不可用。

## 完整复刻新增原图编辑：填写修改后附原图编辑

- 工作台的完整复刻新增「生图方式：文生图 / 原图编辑」。
- 逆向时 Agent 扫描图中可编辑的元素，例如脸部、妆容、姿势、背景和文字：
  - 有人物时必列脸部特征与姿势。
  - 「当前」值用部位短语描述；姿势写各段的朝向与角度。
- 逐项填写修改并提交后，本机服务按提示词版本校验修改、拼装编辑提示词，与原图一起交给生图渠道。编辑提示词冻结到生图记录。
- 编辑提示词的写法：
  - 每项修改写成「图中为…，改为…」。
  - 没改的元素按「当前」描述列为「保持不变」。
  - 修改未涉及的方面与原图一致，包括身份、各部位朝向与角度、构图机位、光色和材质。
  - 保持项与修改冲突时，以修改为准。
  - 修改只波及必然连带的局部，例如新衣物的褶皱与投影。
- 之前逆向的版本没有可编辑元素，需重新逆向才能使用原图编辑，文生图不受影响。逆向并生图、批量完整复刻和轻量面板仍是文生图。

## 完整复刻提示词更易被生图模型执行，自动尺寸跟随参考图

- 复刻提示词的写法：
  - 首句用标准技法或媒介术语定性，例如厚涂（impasto）、赛璐璐（cel shading）、半调网点（halftone）。多步工艺写清先后顺序。
  - 随后写画幅、机位、主体位置占比和关键结构比例。
  - 再分区域写色彩、明暗和笔触尺度。
  - 不再写「还原参考图」这类没有画面信息的句子。
- 提示词是一篇连贯的描述：
  - 神态写进姿态句与五官短语，例如「正面直视镜头」「饱满微张裸粉唇」。
  - 整体情绪在结尾用一句收束。
  - 不再分出「人物神态与微动作」「整体情绪与氛围」两个带标题的段落。其他路径不变。
- 尺寸选「自动」时，按参考图的宽高比追加比例约束：
  - Codex 内置渠道通过提示词约束。
  - OpenAI 与 Gemini 直连还按该比例请求尺寸。
  - Magpie 仍用网关的默认尺寸。

## 主体外貌按部位写，轻微侧身和转头不再画成正面

以下适用于所有逆向路径。

- **外貌按部位写：** 先写主体类别，例如「成人东亚女性」「成年橘色短毛猫」「哑光陶瓷马克杯」。再写服装、发型、毛色等外层造型。最后逐个部位写形状、大小、颜色与状态，例如「杏仁大眼，柔和平眉，细窄鼻梁，饱满微张裸粉唇」，并使用美妆、发型、服装和产品工艺的行业词。
- **写实照片的成像特征：** 写清晰度分布，即焦点落在哪些部位、哪些边缘柔化；写修图程度；写一个贯穿背景、光与后期的色调主词。
- **多个主体：** 每个主体以画面位置加主体类别起句，外貌只写在自己的句子里。共享的光、色调和清晰度只写一次。
- **侧身与转头：**
  - 按头、视线、肩胸、骨盆逐段比较左右两侧的可见证据，定出方向和近似角度，例如「上身向画面右侧转约 30°，画面左侧肩膀靠近镜头、显得更宽；脸转回约 15°，目光看向镜头」。
  - 偏转是辨识关键时，排除项写明「双肩正对镜头，身体端正对称」。
  - 物体和动物同样记录朝向与可见面。

## 认得出的角色、地标与产品直接写出名字

- **识别：**
  - 逆向时先识别画面中的已知角色、吉祥物、地标、艺术作品或产品型号。
  - 用稳定标志核对候选，例如发型、瞳色、标志饰物、建筑轮廓、产品外形，两项以上吻合才确认。
  - 同人图换了服装或画风也能认出。
- **写名字：** 确认后在主体类别后写出专名，例如「日向雏田（Hinata Hyuga，《火影忍者》）」，观察摘要写明识别依据。
- **具名后精简外貌：**
  - 与原作一致的脸型五官、发型发色、瞳色和体型，简写成一个短语，避免逐部位的细节把角色画偏。
  - 与原作不同的服装饰品照图写；神态、姿态朝向、构图、光色和画风也照图写。
- **不识别的情况：**
  - 只凭 Agent 已有的知识识别，不联网。
  - 想不出具体候选时只写外观，不猜名字。
  - 真实人物（含公众人物）不按长相具名；真人 cosplay 可写所扮的角色。
  - 原图编辑的可编辑元素仍完整描述外观，不写专名。

## 改选生图渠道后可立即保存设置

- 修复前：「设置中心 › 生图渠道」载入为 Magpie 后立即改选其他渠道，较慢的设备上「保存生图设置」可能一直不可点，要重新选择渠道才恢复。
- 现在：改选渠道会结束尚未开始的 Magpie 模型读取，保存按钮随即可用。

## 升级方式与数据

**从 v0.8.0 或 v0.8.1 一键安装升级：**

1. 等任务结束。
2. 在「设置中心 › 本机连接」点「检查更新」，再点「升级到 0.9.0」。完成后扩展自动重新加载。
3. 刷新已打开的网页。

v0.8.x 不会为本版弹出提醒，也不显示更新要点。升级到 0.9.0 后，此后的版本才会提醒。

**从 v0.7.0 一键安装升级：**

1. 再运行一次安装命令。
2. 在扩展管理页重新加载 QC-Reframe。
3. 刷新已打开的网页。

**源码安装：**

1. 保存编辑，等任务结束。
2. 把完整仓库更新到 `v0.9.0`。
3. 运行 `npm run setup`，再运行 `npm start`。
4. 重新加载扩展，刷新工作台和网页。

新版本提醒需要扩展与本机服务都是 0.9.0。

**数据与权限：**

- 本版不新增扩展权限：提醒使用 v0.3.0 起已有的通知与定时权限。
- 无需数据迁移。跳过的版本写入 v0.8.0 起已有的 `.local/config/upgrade.json`。
- 项目、提示词、图片、生图渠道与服务配置保存在 `.local/`，全部保留。
- 新的逆向规则在重新逆向后生效，已有提示词不自动改写。要对某张图使用原图编辑，需先重新逆向它。
- 不修改 Codex、Pi 或 Claude Code 的全局配置。

## 验证与已知限制

- **发布前：** 本机通过类型检查、构建与全部产品测试。发布标签的完整回归在 Release 工作流中重新运行，通过后才发布。附件大小与校验值以 Release 页面及 `SHA256SUMS` 为准。
- **检查更新与提醒：**
  - 「发现新版本」「跳过此版本」在合成预览中核对过；GitHub 访问受限的提示在开发版服务上手动核对过。
  - 已安装扩展中的系统通知与 `NEW` 角标尚未实际核对，要等 0.9.0 之后的正式版本发布时才能看到。
  - 从 v0.8.x 插件内升级到本版，发布后核对。
- **原图编辑：**
  - 三个界面场景在合成预览中通过，开发版也实际用原图编辑生过图。
  - 之后加强的「保持不变」写法只由自动测试覆盖，未用真实生图对比。
- **专名：**
  - 开发版真实逆向中，一张同人图在加入识别步骤后写出了角色名。
  - 具名后的外貌简写尚未用真实生图核对。
  - 部分生图渠道可能拒绝版权角色名。具名后身份主要靠名称，被拒时可删去名称、补写外貌后再生图。
- **外貌、朝向与专名规则：** 这些规则改变的是模型行为，自动测试只核对提示词约定，不保证每张图的效果。
- **生图渠道保存修复：** 修复前，相关界面场景每次都能复现问题；修复后全部通过。
