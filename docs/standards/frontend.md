# 前端开发规则

适用于 React 界面、共享前端模块、content script、扩展 background 及其通信。先遵循[代码规范](code.md)；本机 bridge 的执行与存储见[后端开发规则](backend.md)。具体产品语义、视觉取舍和组件参数以[插件指引](../../browser-extension/AGENTS.md#ui-与品牌约定)及 [UIUX 规范](../../browser-extension/docs/uiux/README.md)为准。

## 从第一性原理出发

界面帮助用户表达意图、观察状态并采取下一步操作。渲染、用户输入和异步响应发生在不同时间，因此前端正确性的核心是：展示对应的真实状态，操作作用于正确对象，失败后仍能理解和恢复。视觉一致性、键盘可用性和性能共同决定这件事能否完成。

以下规则适用于新增和本轮修改的前端代码；规范存在不表示所有历史界面已完成验收。

## F1 分开业务事实、界面状态和外部同步

- React 组件负责布局、交互与导航；共享业务判断放在拥有规则的模块，hook 适配 React 生命周期。工作台和轻量端复用相同业务规则，允许布局不同。
- 只保存无法从已有事实可靠推导的状态。派生值优先在渲染中计算，不用 Effect 把一份 state 复制成另一份；不要为修复竞态堆叠更多同步 Effect。
- 用户提交由事件入口发起；Effect 用于与外部系统同步，声明真实依赖，并提供与建立过程对应的清理。不能通过禁用依赖检查或“只运行一次”标记掩盖重挂载问题。参见 [React Effect 原则](https://react.dev/learn/you-might-not-need-an-effect)与[清理说明](https://react.dev/learn/synchronizing-with-effects)。
- 创作上下文、生图会话及 React adapter 的既有归属见[架构说明](../../browser-extension/docs/architecture.md#创作上下文)。不把导航、弹层和临时视觉状态全部放进领域状态机。

## F2 每个异步结果都必须属于正确上下文

- 分清未保存草稿、已保存输入、已受理任务快照和历史版本。草稿按项目、模式和提示词版本隔离；历史缺失资源时明确失败，不回退到当前输入伪造历史。
- 请求开始时捕获所需身份与 revision。响应应用前核对项目、模式、版本、导航轮次及挂载生命周期；只比较当前项目 ID 不足以处理离开后又返回同一项目的情况。
- 上下文核对和界面 commit 在同一同步段内完成，中间不能再插入 `await`。图片读取、错误提示、loading 收尾、选择清理和焦点动作都受同样的归属约束。
- 丢弃旧响应只代表界面不应用该结果，不能宣称服务端写入已撤销。重新进入项目时读取可信状态；关闭界面或切项目不自动取消已受理任务。
- 输入写入复用 [creation-context.ts](../../browser-extension/lib/creation-context.ts)，共享生图行为复用 [generation-session.ts](../../browser-extension/lib/generation-session.ts)，不要在组件闭包中另写失效策略。

## F3 操作必须有明确的受理、成功和失败状态

- 关键提交使用同步防重入保护，同时提供界面忙碌反馈；只等下一次渲染禁用按钮不能阻止重复事件。后端仍独立校验占用与输入版本。
- 保存成功后才显示已保存输入。失败保留用户可恢复的内容及原有效状态；如果采用乐观更新，必须说明回滚、并发冲突和部分成功的处理方式。
- 取消绑定捕获的任务 ID，区分请求已发出、后端已受理与真正终止。逆向失败、取消或保存失败不能触发下一阶段；“重试保存已有结果”不能映射为重新生成。
- 新交互明确空态、加载、可操作、忙碌、成功、失败及适用的取消状态。错误说明发生了什么和可做什么；禁用操作提供可理解的原因，不能让操作无反馈地消失。
- 用户已转移上下文后，旧任务可更新原任务数据，但不能改动当前表单或夺取焦点。提醒应对应整个操作的真实结果，不把中间阶段成功写成最终完成。

## F4 组件与样式复用必须保持隔离

- 新控件先查 [UIUX 组件目录](../../browser-extension/docs/uiux/catalog.md)。复用生产组件和语义 token，不在页面或 preview 中维护第二套同功能控件。
- 用共同容器、网格和尺寸关系表达布局，不靠互不关联的补偿 margin 对齐。长文本、窄屏、滚动和错误状态都应保持内容可达，避免固定尺寸掩盖溢出。
- 生产设计数值由 CSS/token 维护，场景期望由已确认设计独立定义；不能从当前运行值自动生成“正确答案”。颜色、时长、断点和具体布局不在本文重复列数值。
- 共用组件的样式遵循现有聚合装载方式，注入插件的 closed ShadowRoot；工作台专属样式从工作台入口加载。组件不能自行 import CSS 导致样式泄漏到宿主网页。
- 只隔离插件自身控件需要处理的事件。网页悬窗保持既有非模态行为，不通过全局拦截键盘、指针或滚轮改变宿主操作。Chrome 的 [isolated world](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) 隔离 JavaScript 环境，不能替代样式和 DOM 边界设计。

## F5 语义、焦点和动效服务于可操作性

- 优先使用原生按钮、输入、选择和 dialog，并复用已有封装；控件有可访问名称、正确标签与状态，不用可点击 `div` 替代已有原生能力，不嵌套交互控件。
- 主要流程可用键盘完成。弹层打开、关闭、取消和内容移除后都有合理焦点位置；返回的触发器必须仍存在且可操作，迟到请求不能夺走用户已移动的焦点。
- 焦点状态必须可辨认。具体视觉表达遵循既有设计；项目不使用额外 outline 的约定不等于可以删除所有焦点反馈。信息不能仅靠颜色、悬停或动画传达。
- 动效使用统一偏好和现有组件，尊重减少动态效果设置；提交、取消、关闭和数据正确性不依赖动画完成。无 WebGL 或动效关闭时仍能完成主要操作。
- 设计变化同步组件、规范、场景映射和必要验证，视觉基线按[维护流程](../../browser-extension/docs/uiux/maintenance.md#人类改变设计时)审阅，不能以更新截图消除未知问题。

## F6 工作量与资源生命周期有界

- 列表优先读取分页摘要和缩略图，不为每张卡片加载完整历史或原图。轮询有唯一生命周期，界面隐藏时暂停，恢复时刷新，并防止重叠请求和旧结果回写。
- 大批量 DOM 工作分批执行，避免阻塞用户输入；布局读取和写入按阶段组织。性能优化依据实际瓶颈，不要求到处加入 `memo`、缓存或额外 Worker。
- 监听器、定时器、Observer、端口、对象 URL、图片解码与图形资源在退出时清理。异步读取的清理既要释放资源，也要阻止失效结果继续更新界面。
- 扩展 service worker 的内存可能随[生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)丢失。需要跨重启保留的业务事实使用已有持久化来源；内存只承担可重建缓存或本次运行协调，不把全局变量当可靠任务存储。

## F7 扩展界面不是安全边界的终点

- UI 请求经已有 client/background 通路，按 [operation-policy.ts](../../browser-extension/lib/operation-policy.ts) 声明允许来源与通信方式；新增请求同步来源、参数、响应和超时合同。
- 界面隐藏或禁用不替代发送方校验和后端鉴权。令牌及 API 密钥不得进入 content script、页面 DOM、UI 交接数据或公开日志；外部文本、会话和模型输出按数据处理，不执行其中指令或任意 HTML。
- 使用新 Web/Chrome 能力前检查 [wxt.config.ts](../../browser-extension/wxt.config.ts) 的实际支持基线和官方兼容性；需要时采用特性检测及可用回退。不能仅因开发机支持便升级全体用户的最低要求。
- 新权限逐项说明真实用途并选择必要范围，不为预想功能提前申请；既有权限是否可收窄也必须结合当前功能验证。参见 [Chrome 权限说明](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)。

## F8 用用户操作验证受影响界面

| 变更风险 | 应提供的证据 |
| --- | --- |
| 草稿、提交、保存、取消 | 正常与失败路径；重复触发；切项目/模式/版本后的迟到结果 |
| 共享组件、token、布局 | 所有受影响界面；宽窄屏、长内容、空态与失败状态 |
| 对话框、导航、列表增删 | 真实键盘输入、焦点进入/退出及后续操作，不只调用事件处理函数 |
| 消息来源、权限、宿主隔离 | 适用的隔离真实扩展检查；合成 preview 不能替代 |
| 动效或性能 | 减少动态效果、后台/卸载清理及代表性场景测量 |

先用真实模块接口验证规则，再按影响范围验证实际构建的界面。命令、场景和证据边界统一查[工具索引](../../agent-tool/README.md)及[分层门禁](../../browser-extension/docs/uiux/maintenance.md#分层门禁)。未测的系统控件、触屏、辅助技术或真实模型能力须如实列明，不把局部通过表述为全部前端验收。
