# 后端开发规则

适用于本机 Node bridge、CLI/RPC 与生图渠道适配、任务调度、文件存储和服务管理脚本。先遵循[代码规范](code.md)。当前系统是本机服务，不因本规范引入数据库、微服务或通用任务框架；执行边界见[架构说明](../../browser-extension/docs/architecture.md)。

## 从第一性原理出发

后端把用户意图变成持久数据和外部副作用。网络、进程和文件操作可能失败、重复、乱序或只完成一部分，因此正确性取决于三件事：谁有权执行，哪一刻算成功，失败后还保留什么。接口、锁、快照、恢复与测试都要服务于这些边界。

以下约束适用于新增和本轮修改代码。规则不会自动赋予存量接口幂等性、跨文件事务或断电耐久性；声称某项保证前必须有实现和验证证据。

## B1 在可信边界校验完整合同

- HTTP 入口负责认证、来源检查、参数解析和调用装配，领域模块负责业务规则，adapter 负责外部协议。新增端点明确允许调用者、输入、输出、错误、超时与副作用。
- 本机 loopback 不代表可信。保留 Host、Origin、Bearer 与扩展消息来源校验；连接握手仅接受本安装批准的扩展来源。浏览器 CORS、前端禁用和类型声明不能替代授权检查。
- 外部输入检查结构、枚举、数量、长度、有限数值及关联关系；后端独立计算业务派生字段，不信任客户端提交的归一化尺寸、资格或版本归属。
- 接口优先接业务 ID，再由拥有资源的模块解析路径。不得把请求参数直接交给文件系统或 shell；必须接受相对路径的已有场景要验证规范化后的允许目录及适用的符号链接边界。
- 配置和 API 错误响应只返回必要安全字段。连接、模型目录、配置完整和真实执行成功是不同状态，不能混为“已验证可用”。具体信任范围查[连接与模型边界](../../browser-extension/AGENTS.md#连接模型和图片边界)。

## B2 受理时冻结意图，执行时只读该次快照

- 冻结该任务需要的项目、模式、提示词版本、图序、语言、尺寸、Agent/provider/model 及账号上下文。自动衔接和排队使用原快照，不在执行时重新读取当前表单或全局设置。
- 服务端在受理前重新验证资格和资源引用；前端预检不能保证提交时仍有效。未知或不可用的渠道明确失败，不静默改模型、切渠道或改变用户输入。
- 凭据只保留在私有配置与必要的执行期内存，不进入任务、批次、历史响应或公共报告。任务结束后释放不再需要的敏感快照；重启不读取新密钥继续旧请求。
- 原快照与当前账号、provider 或 CLI 上下文不再兼容时明确拒绝，不能用新配置解释旧任务。历史兼容只接受已定义的缺省语义，具体规则见[架构的生图渠道](../../browser-extension/docs/architecture.md#生图渠道)。

## B3 并发、取消与重复请求具有明确语义

- 在拥有资源的模块内串行化冲突写入，并在锁或队列内部核对 revision；锁外预检不能防止跨窗口旧写入。锁的范围、持有者和释放时机必须覆盖真实临界区。
- 任务占用覆盖执行、终态保存和自动阶段交接。每个任务有独立取消信号；取消请求发出或界面关闭不等于执行已停止，不能提前允许冲突任务、维护操作或资源回收。
- 取消和保存失败阻止后续阶段启动；迟到成功回包不能把已取消任务复活。终态收尾要能面对重复回调，避免重复发布或重复触发外部操作。
- 每个产生副作用的接口明确重复提交语义。有幂等键的接口必须校验同键同体，冲突明确拒绝；没有幂等保证时不能对网络错误自动重放写入或付费请求。
- 区分未受理、受理结果未知、执行失败和保存失败。未知结果先查询或沿已定义的同键请求恢复；“重试保存已有图片”只保存原输出，不新建 generation、不再次调用模型。
- 超时设置在拥有操作的层。受理前传递请求的取消和期限；受理后使用任务自身的取消信号与期限，客户端断连不自动取消已受理任务，客户端恢复后查询任务状态。任务已取消或超时后不得再启动新阶段；取消只能声明本地实际保证，不承诺上游撤单或免计费。

## B4 成功只能在可信提交之后发布

- 保存调用时冻结需要写入的内容；有序写临时文件并原子替换成功后，才发布任务 feed 或已保存成功。执行中的可变对象不等于已提交快照。
- 写入失败保留旧有效记录和必要恢复信息，主操作失败如实返回。未提交引用仍受保护，不能因磁盘列表没有新记录就回收其图片。
- 原子 rename 只提供对应文件替换边界，不自动提供多文件事务、跨进程互斥或断电落盘保证。增加这些承诺前先明确协议和故障证据，不能只靠函数名声称“事务”。
- 涉及多个文件的操作明确写入顺序、提交点、可重入恢复和最后清理步骤。需要关联记录时先保存恢复关联，再写产物，最后提交业务记录；不能先删原件再尝试保存新状态。
- 当前实现与边界见 [task-records.mjs](../../browser-extension/bridge/task-records.mjs)及[运行与持久化](../../browser-extension/docs/architecture.md#运行与持久化)。

## B5 恢复优先于迁移和清理

- 项目身份与图片内容哈希分开。不可变资产被当前输入、历史或其他任务引用时不能原位覆盖；隐藏、移除某处引用和物理删除是不同操作。
- 回收先构建完整引用集合，包含各模式输入、历史、生成记录、排队批次、未提交写入和待保存关联。来源损坏或无法确认完整性时保守停止回收，保留原件并报告原因。
- 迁移先验证新数据和引用，提交成功后再删除旧文件。保留合法旧字段语义及显式空值，不能因解析或迁移失败把用户数据重置为空。
- 启动恢复在依赖它的清理之前完成。一般损坏记录不应遮蔽无关可恢复任务；若损坏涉及关键恢复索引或无法保证资产安全，则停止相关操作，必要时停止启动，不能继续冒险清理。
- 服务重启按既有合同结束中断任务，不自动重跑模型；已取消、已删除和已完成任务不复活。仅保存在内存的图片无法承诺跨重启恢复，错误与 UI 必须说明这一限制。
- 复用 [generation-output.mjs](../../browser-extension/bridge/generation-output.mjs) 的保存恢复与既有资产模块，不新增绕开引用保护的清理入口。

## B6 外部 I/O 有界、可取消且最小授权

- 网络请求明确允许的 scheme、主机范围、鉴权目标、重定向策略、总耗时、响应字节和解码限制。配置 API 地址、网关地址和返回图片 URL 是不同信任边界，按各自合同验证。
- 向外部 URL 下载图片不转发原 API 密钥；不能仅凭扩展名或 Content-Type 信任内容。图片解码验证实际格式和像素，超限明确拒绝，禁止无界缓冲或解压。
- 本机路径、URL、模型输出和会话文本是数据，不是执行权限。子进程使用已核实入口和固定参数数组；不得将用户或模型文本拼接为 shell 命令。
- RPC 只开放任务需要的能力；未知调用拒绝。CLI 安装更新与任务互斥，操作前后验证来源和上下文，部分失败也要使已不可信的能力验证失效。
- 队列、并发、读取和重试都有明确上限。仅对可证明安全、合同允许的操作采用有界重试；不能用无限等待、自动切 provider 或静默截断掩盖失败。
- 具体渠道、下载和 CLI 策略保留在[插件边界文档](../../browser-extension/AGENTS.md#连接模型和图片边界)，不把供应商当前行为写成永久平台保证。

## B7 诊断必须指出失败所在阶段

- 区分参数、认证、状态冲突、外部执行、保存与恢复失败；不能把所有 RPC 错误归成版本问题，或把保存失败归成模型没生成图片。
- 沿用[代码规范的错误与日志规则](code.md#c5-错误必须保留真实状态)，关联信息足以定位任务和阶段，错误文案说明原数据是否保留、是否可重试及重试会不会再次产生外部副作用。
- 维护命令只能操作自己管理的进程和目录，不能为解决冲突杀死不明进程、改动用户全局模型配置或清空真实项目。工具与服务管理入口见[贡献指南](../../Contribution.md#实现与验证)。

## B8 用故障验证合同

| 变更风险 | 必须考虑的验证 |
| --- | --- |
| 参数、鉴权、路径、下载 | 合法请求、非法来源、越界参数、禁止目标和超限响应 |
| 任务与队列 | 重复提交、并发冲突、排队后改设置、阶段交接取消和迟到完成 |
| 持久化与恢复 | 临时写/替换/终态保存失败；部分提交后重启；恢复失败保留原件 |
| 资产与迁移 | 旧记录、显式空输入、多处共享引用、待保存引用和损坏引用保护 |
| provider、CLI、RPC | 固定请求合同、错误分类、超时取消、输出校验、账号或入口变化 |

按实际影响选取场景，通过真实模块接口注入 I/O 故障，使用临时目录、合成资源和受控执行器。预览固定返回值不能证明后端持久化或幂等性；模拟 provider 也不能证明真实模型可用。真实账户、用户数据和付费调用按本次授权及[验证流程](../../Contribution.md#实现与验证)执行，并单独报告证据范围。
